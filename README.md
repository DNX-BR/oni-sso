# ONI-SSO

CLI Tool to Login in AWS with Azure SSO (SAML), Google SSO(SAML) and AWS SSO

## Public Repository Image

https://gallery.ecr.aws/dnxbrasil/oni-sso

## Installation

```bash
git clone git@gitlab.com:dnx-br/utilities/oni-sso.git
cd oni-sso
docker build -t oni-sso:latest .
# or use our public image
docker pull public.ecr.aws/dnxbrasil/oni-sso:latest
```



## Usage
```bash
Usage: oni-sso [options]

Commands:
  auth-google [options]  Command for login by Google SSO
  auth-azure [options]   Command for login by Azure SSO
  auth-aws [options]     Command for login by AWS SSO
  assume-role [options]  Command for assume role

Options:
  -v, --version  Show Version                                         [bool]
      --help     Show help                                            [bool]

You need at least one command
```


## Examples

> The Google/Azure flows run a headless browser inside the container. Keep `-it` so the interactive
> prompts (MFA confirmation, AWS SSO device code) work. Read the MFA number from the terminal and approve on your phone.

```bash
# Build the image
docker build -t oni-sso:latest .

# Azure login (console output). Mount ~/.oni-sso to persist the "trusted device" profile across runs.
docker run --rm -it \
  -v "$PWD:/work" \
  -v "$HOME/.oni-sso:/root/.oni-sso" \
  oni-sso:latest auth-azure -a <appIdUri> -t <tenantId> -o console

# Google login (console output)
docker run --rm -it \
  -v "$PWD:/work" \
  -v "$HOME/.oni-sso:/root/.oni-sso" \
  oni-sso:latest auth-google -i <idpid> -s <spid> -o console

# AWS SSO login (device authorization flow). Prints a URL + code to open in any browser.
docker run --rm -it -v "$PWD:/work" oni-sso:latest auth-aws -u <sso-start-url> -o console

# Assume role (reads /work/.env.oni-auth generated by an auth-* command)
docker run --rm -it -v "$PWD:/work" oni-sso:latest assume-role -r <role-arn> -o console

# Assume role -> AWS profile file
docker run --rm -it -v "$PWD:/work" -v "$HOME/.aws/credentials:/profile/credentials" \
  oni-sso:latest assume-role -r <role-arn> -o profile -p dev
```

On Windows PowerShell, use `${PWD}` and `$env:USERPROFILE`:

```powershell
docker run --rm -it `
  -v "${PWD}:/work" `
  -v "${env:USERPROFILE}\.oni-sso:/root/.oni-sso" `
  oni-sso:latest auth-azure -a <appIdUri> -t <tenantId> -o console
```

> Notes for containers:
> - The persistent profile (`-v .../.oni-sso:/root/.oni-sso`) is what lets the IdP remember the device and skip MFA on later runs.
> - Inside the container the browser is always headless. If a brand-new Google profile triggers a captcha, seed it once locally with `ONI_HEADFUL=1` and reuse the same `~/.oni-sso` volume.
> - Output `console`/`export` print to stdout; `env`/`one`/`profile` write to mounted paths (`/work`, `/one`, `/profile`).

## MFA Support

| Provider        | Support?           | Types  |
| ------------- |:-------------:| -----:|
| Google      | yes | `Msg Code Text and Voice`, `Google Requests`, `Google Authenticate` |
| Azure      | yes      |   `Msg Code Text and Voice`, `Number matching` |
| AWS | yes      |   Handled natively by IAM Identity Center (device authorization flow) |

> Note: `auth-aws` uses the official AWS IAM Identity Center **device authorization (OIDC)** flow. It prints a verification URL + code; open it in any browser to approve. It no longer scrapes the AWS portal and does not prompt for username/password.

## Common auth-* and assume-role option
```bash
  -o, --output-format     Credentials output format
                 [options: "console", "one", "env", "export", "profile"]
  -d, --duration-seconds  AWS Session duration in seconds [default: 3600]
  -p, --profile-name      AWS profile name               [default: "default"]
  -m, --monitor           Take screenshots of auth steps in /tmp (auth-google/auth-azure)
```
> WARNING: assume-role not work with auth-aws

## Extra settings
* Login in AWS use default region us-east-1 if environment variable AWS_DEFAULT_REGION is not set
* To avoid setting the appIdUri and tenantId every time on azure login, export the environment variables AZURE_APP_ID_URI and TENANT_ID
* To avoid setting the idpId and spId every time on google login, export the environment variables GOOGLE_IDPID and GOOGLE_SPID
* To avoid input username and password every time (Google/Azure), you can export environment variables ONI_USERNAME and ONI_PASSWORD
* `SSO_REGION` (auth-aws): region of the IAM Identity Center instance (falls back to AWS_DEFAULT_REGION, then us-east-1)
* `MFA_TIMEOUT` (ms, Azure): how long to wait for the MFA number-matching screen (default 60000)
* `TIMEOUT_PAGE` (ms): delay between authentication steps (Google default 2000, Azure default 5000)
* `ONI_DIAG_DIR`: directory where failure diagnostics (screenshot + HTML) are written (default %TEMP%/oni-sso)
* `CHROME_PATH`: optional path to a Chromium/Chrome binary (Playwright uses its bundled browser by default)
* `ONI_HEADFUL=1` (or `HEADLESS=false`): run the browser visibly (useful to debug a login)

## Device trust / session persistence
By default the Google/Azure browser flows use a **persistent profile per provider** (cookies survive between runs),
so the IdP can remember the device and skip password/MFA within the policy window. Credentials are only prompted
when the email/password fields actually appear — on a trusted device nothing is asked.

* `ONI_PROFILE_DIR`: base dir for the persistent profiles (default `~/.oni-sso/profiles`). Per-provider subfolders.
* `ONI_NO_PERSIST=1`: disable persistence (use an ephemeral browser session each run).
* Security: the profile stores session cookies (equivalent to being logged in). Keep it private; don't use a shared dir.
* Docker: to persist across containers, mount the profile dir as a volume, e.g. `-v $HOME/.oni-sso:/root/.oni-sso`.

## Requirements
* Runs on Node.js >= 22.12 (the published image is based on the official Playwright image). The browser flows (Google/Azure) use Playwright; AWS SSO uses the AWS SDK and needs no browser binary.
